title: Spring Boot/Cloud 配置优先级详解笔记
---

## 一、核心配置源优先级（从高到低）
1. **命令行参数**  
   直接通过命令行传入的参数（如 `--server.port=8080`）优先级最高，会覆盖其他所有配置源的同名配置。

2. **环境变量与系统属性**  
   操作系统环境变量（如 `SPRING_PROFILES_ACTIVE=dev`）和 JVM 系统属性（如 `-Dspring.profiles.active=dev`）优先级高于配置文件。

3. **外部配置文件**  
   项目外部的配置文件（非类路径下），优先级规则：  
   - 路径优先级：`file:./config/`（项目根目录的 config 文件夹）> `file:./`（项目根目录）> `classpath:/config/`（类路径的 config 文件夹）> `classpath:/`（类路径根目录）。  
   - 同路径下，profile 配置文件（`application-{profile}.properties/yaml`）> 默认配置文件（`application.properties/yaml`）。这是指定了某个profile配置文件的情况，如果涉及到多环境配置，一般都会指定，如果没有指定，那么生效的依然是`application.properties/yaml`，同目录下的`application-{profile}.properties/yaml`并不会生效。


4. **内部配置文件**  
   项目内部的配置文件（类路径下），优先级规则与外部配置文件一致（路径优先级 + profile 优先级）。

5. **配置中心**  
   若使用 Spring Cloud 配置中心（如 Nacos、Apollo），其配置优先级介于环境变量和外部配置文件之间（具体位置依框架而定）。


## 二、配置文件类型与加载规则
1. **properties 与 yaml 的优先级**  
   同路径下，`properties` 文件优先级高于 `yaml` 文件。  
   原因：Spring Boot 会先加载 `yaml` 配置，后加载 `properties` 配置，后加载的内容会覆盖先加载的同名配置。

2. **默认配置与 profile 配置**  
   - **默认配置文件**：`application.properties` 或 `application.yml`，任何情况下都会被加载（除非被更高优先级配置覆盖）。  
   - **profile 配置文件**：命名格式为 `application-{profile}.properties/yaml`（如 `application-dev.yml`、`application-prod.properties`），仅在对应的 `profile` 被激活时生效。  
   - 优先级：激活的 profile 配置文件 > 默认配置文件。  
   - 生效规则：**同名属性覆盖，异名属性合并**。例如：  
     - 默认配置属性有 `server.port=8080` 和 `app.name=myapp`；  
     - 激活的 `prod` 配置属性有 `server.port=8081` 和 `db.url=prod-db`；  
     - 最终生效：`server.port=8081`（被覆盖）、`app.name=myapp`（保留）、`db.url=prod-db`（新增）。


## 三、多 profile 激活与优先级
1. **激活方式**  
   通过 `spring.profiles.active` 参数进行指定，有以下三种方式：
   - 命令行（`--spring.profiles.active=dev`）
   - 配置文件（`spring.profiles.active=test`）
   - 环境变量（`SPRING_PROFILES_ACTIVE=prod`）。

3. **多 profile 优先级**  
   同时激活多个 profile（如 `spring.profiles.active=dev,test`）时，**后激活的 profile 会覆盖先激活的**。例如：  
   - `dev` 配置 `server.port=8080`，`test` 配置 `server.port=8081`；  
   - 最终生效 `server.port=8081`（`test` 覆盖 `dev`）。

3. **未激活 profile 的情况**  
   若未设置 `spring.profiles.active`，则仅默认配置文件（`application.properties/yaml`）生效，所有 `application-{profile}` 配置文件均不加载。


## 四、Spring Cloud 中的 bootstrap 配置
1. **优先级**  
   `bootstrap.properties/yaml`（及对应的 `bootstrap-{profile}.properties/yaml`）优先级高于所有 `application` 相关配置，且不会被 `application` 配置覆盖。

2. **使用场景**  
   主要用于加载启动阶段必需的配置，如配置中心地址（`spring.cloud.nacos.config.server-addr`）、服务注册中心地址等。

3. **自身规则**  
   遵循与 `application` 配置相同的路径优先级和 profile 优先级（如 `bootstrap-dev.yml` > `bootstrap.yml`，外部路径 > 内部路径）。


## 总结
- 配置优先级核心逻辑：**命令行 > 环境变量/系统属性 > 外部配置 > 内部配置 > 配置中心（依框架）**，bootstrap 配置独立且优先于 application 配置。  
- 配置文件间的关系：**路径优先、profile 优先、后加载覆盖先加载**，且始终遵循“同名覆盖、异名合并”原则。  
- profile 是环境标识，需通过 `spring.profiles.active` 激活，未激活的 profile 配置文件不生效。
